- Publish a release only when the user explicitly authorizes it and chooses the version. Follow `RELEASING.md` exactly.
- Release metadata matching must accept both LF and CRLF and preserve line endings; repeated preparation must not duplicate headings or change dependency versions. Keep `test/test_release_metadata.py` as the boundary regression.
- Before committing or packaging release-facing artifacts, remove or generalize personal machine paths, credentials, private target names, and any details that reveal which real program or protected sample was being debugged; use synthetic fixtures and neutral examples instead.
- Use `docs/DEVELOPMENT_TOOLS.md` as the catalog for reusable MCP scenario, trace-validation, parity, and IPC-compatibility tooling; extend those tools instead of adding one-off harnesses when practical.

- After a successful VEH Debugger build, use the `agent-tool` `copy` tool to deploy `veh-mcp-server.exe`, `veh-debug-adapter.exe`, and the required `vcruntime_net*.dll` beside `agent-tool.exe`, verifying exact paths and copied hashes first.
- When this repository has a changelog or release-notes file, record completed user-facing changes under an `Unreleased` section as part of the same task so the next release notes are ready.
- When adding a public MCP tool or extending a tool with batch-meaningful behavior, wire it into `veh_batch` and breakpoint actions unless the operation is inherently unsafe or nonsensical there. Keep direct, batch, and action result semantics in parity and add integration coverage for each supported path; document any deliberate exclusion.
- Anything that depends on target state (memory scan, memory map, protection, threads, calls) must be a backend IPC command handled inside the target, not a client-side loop over `read_memory`, so a future driver/hypervisor backend can implement the same command. Pure computation (assembling, formatting) stays client-side.
- Test harnesses that launch a target, adapter, or MCP server must use real non-blocking timeouts and `try/finally` cleanup. They must terminate and wait for every process they started on success, assertion failure, timeout, and interruption.
- After tests, verify that no `test_target`, adapter, or MCP server started by the current work remains. Before terminating a leftover process, match its executable path and verify its full parent chain; never classify or terminate a process by age alone, and never touch unrelated active terminal/session trees.
