# VEH Debugger v1.2.3

This release adds persistent analysis comments and labels to the existing MCP
inspection tools. Notes can be reopened across sessions, retain their evidence
and revision history, and appear alongside the addresses being inspected.

## Upgrade notes

- No new MCP tool or database dependency is required. Manage notes through
  `veh_symbolize(analysis=...)`; ordinary debugging remains unchanged when no
  analysis directory is selected.
- Choose a local analysis directory once. Edits auto-save to `analysis.json`, and
  the selected directory is remembered for restart. Analysis files contain your
  findings and should remain private unless you choose to share them.
- Update the frontend and VEH payload DLLs together for automatic note binding.
  External backends remain optional. Without stable module identity support,
  notes can still be saved and retrieved by ID, but are never automatically
  attached to an address, including within the same session.
- This release exposes notes in MCP results. It does not add a VS Code inline
  annotation editor, replace real PDB/export names, or automatically move notes
  to a different binary build.

## Added

- **Persistent instruction comments and labels.** Store a comment, label,
  before/after position, author, analysis context and short evidence references
  at an instruction. Mark an interpretation as a hypothesis, observation or
  refuted claim without treating one observation as a universal proof.
- **Selectable analysis directories.** Open, create, inspect and close a local
  JSON project through the existing symbol tool. Modules and their old/new builds
  share one analysis file. Launch profiles can explicitly select a directory
  instead of using the remembered one.
- **Build-aware restoration.** Stable image identity and module-relative offsets
  preserve notes across ASLR. Different builds keep their previous findings
  separate. Changed instruction bytes are marked stale and require explicit
  acceptance before replacing the saved code anchor. Module changes during a
  lookup prevent notes from being saved or attached to the wrong image.
- **Search and revision history.** Search notes, page bounded lists, and retrieve
  full evidence or earlier revisions explicitly. Existing edits and deletions
  require the returned revision, including after a record is deleted and recreated.
  Locked, malformed or unsupported files are not silently reset; failed writes
  preserve the previous document.
- **Shared record operations.** Read, write, search and delete notes through direct
  calls, batches and breakpoint actions. Opening or closing a project remains a
  direct operation because it changes which analysis file the frontend owns.

## Changed

- Disassembly and symbol results include short saved-note previews when a project
  is open. Full comments, evidence and history remain explicit queries.
- Confirmed continue/step stop replies can show a short comment and label after
  verifying the thread is still stopped at the returned instruction address.
  Module-load/exit events and stops already resumed by actions do not acquire
  misleading instruction comments.
- Stack traces and active software/hardware breakpoint lists show exact-address
  labels only. Return addresses do not borrow function-entry labels, and pending
  breakpoints remain unannotated. Preview limits report truncation explicitly.
- `include_annotations=false` disables enrichment. List and stack responses do not
  repeat comment bodies, evidence or revision history, keeping routine responses
  compact. No background annotation polling or per-trace-event expansion is added.
