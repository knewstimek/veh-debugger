# VEH Debugger v1.2.2

This release adds bounded symbol-name searches, explicit module selection, larger
value scans, and reusable execution and value-freeze operations. It also improves
guest debugging, instruction-aware code patches, and the accuracy of debugger
results and session recovery.

## Upgrade notes

- Local debugging still uses the VEH DLL by default. External backends are optional
  and are not included; their advertised capabilities determine availability.
  Update the payload DLLs together with the frontend to use the new native features.
- Address expressions accept unambiguous symbols and hexadecimal module offsets
  without `0x`. Duplicate names are not resolved by choosing the first match:
  inspect the candidates, then select an image with `module_base` or
  `0xBASE!Function`. Standalone numeric literals keep their existing interpretation.
- Assembly writes now cover complete original instructions and NOP-fill unused
  bytes by default. Stop relevant target threads before patching. Instruction
  relocation, automatic thread suspension and atomic live patching are not provided.
- Guest launch/stopOnEntry and the explicit guest `stopOnModuleLoad` option remain
  unsupported. DAP exception filtering accepts only `all`; unsupported filter
  configurations now fail instead of appearing to take effect.
- Detour caller recording and PTWRITE are interfaces for supporting external
  backends, not new facilities in the VEH DLL. Hardware and backend support are
  required; existing caller tracing and full PT branch tracing retain their defaults.

## Added

- **Symbol-name search and module selection.** `veh_symbolize(name=...,
  max_results=10)` lists up to ten matching code symbols, including same-name
  functions in different images. Candidates include module bases, paths and loaded
  image address widths when available. Use `module_base="0x..."` with an unqualified
  function name, or `0xBASE!Function` in an address argument, to select one image.
  Ambiguous, truncated, incomplete and forwarded results are not silently used as
  callable addresses. Older backends retain their existing module enumeration;
  unavailable image widths are reported as unknown.
- **Larger, asynchronous value scans.** Supporting backends can keep bounded scan
  generations in RAM or temporary files, push progress/completion events, cancel
  jobs and undo refinements against the appropriate baseline. Automatic results
  show at most 32 candidates; explicit pages remain bounded to 1000. Reset and
  session teardown release owned temporary scan files. Older backends retain the
  original scan interface and limits.
- **Optional basic-block trace capture policies.** `collect_snapshots=false` omits
  register/stack snapshots, while `compress_paths=true` represents consecutive
  repeated paths with exact counts and sequence information. Repeats never cross
  collection gaps, exceptions or observed code changes. These options reduce
  recording/output costs; they do not reduce single-step exception counts.
- **Owned execution operations.** `veh_execution` exposes confirmed execution
  state, runs a selected thread to an address, cancels temporary ownership and
  optionally emits bounded stop notifications. CALL step-over shares temporary
  breakpoint ownership and preserves existing user breakpoints.
- **Leased value freezing.** `veh_value_freeze` maintains up to 16 periodic writes,
  each up to 64 bytes, with explicit leases and intervals. Writes are serialized,
  read back for verification, and stopped after uncertain effects or session loss.
- **Guest debugging and process discovery.** DAP can attach through an external
  guest backend and use its supported execution, memory, thread, module and symbol
  operations. `veh_processes` obtains a guest/VM process snapshot through backend
  IPC, without interpreting guest PIDs as host processes.
- **External instrumentation options.** `veh_trace_callers(mode="detour")` and
  `veh_branch_trace(kind="ptwrite")` expose capability-gated collection with bounded
  summary/page results. Results retain loss, incompleteness, overflow and transaction
  policy information. Original data reads remain the default; optional patched
  reads may expose detour bytes and change integrity/self-read results.

## Changed

- `veh_assemble(write=true)` expands the overwrite span to whole instructions and
  NOP-fills the unused tail, including for longer JMP encodings. `overwrite_size`
  chooses an explicit whole-instruction span and `nop_fill=false` preserves the
  original tail. `raw_write=true` explicitly selects unchecked byte writing.
  Patching requires backend support and rejects software-breakpoint overlaps.
- `veh_step_out` waits for the matching thread's stop and returns its instruction
  pointer. Its timeout accepts 1-300 seconds; a timeout does not cancel execution.
- Host `veh_launch` results include the target address width and initial main-thread
  ID when available. Guest checkpoints and captures use backend memory information;
  guest captures omit unsupported TEB collection by default.

## Fixed

- **Accurate debugger results.** DAP pause, step, continue, memory writes and thread
  termination propagate backend rejection and transport failures. Stack, module and
  thread query failures are distinguished from successful empty results instead of
  inventing frames, threads or completed writes. Unknown execution state stays unknown.
- **Session recovery.** Dead local agents and disconnected pipes can be cleared
  without waiting indefinitely for detach acknowledgements. Live backend refusal
  retains the session; unacknowledged cleanup is explicitly identified. TCP detach
  preserves the resident runner's work-closure confirmation.
- **Deferred function breakpoints.** Supporting guest backends can hold a module-load
  stop while DAP binds pending module-qualified functions, avoiding the module-list
  polling race. Reloads rebind pending functions and shared breakpoint IDs are
  preserved. Confirmed loader stops remain available for explicit continuation.
- **Loader-safe symbol updates.** Loader notifications defer symbol-cache changes
  to the serialized lookup path. Unload/reload invalidates stale module symbols,
  and namespace changes during a search mark the result incomplete.
- **Address and partial-write safety.** Address expressions reject overflow and
  values outside a known 32-bit target. Duplicate module basenames require explicit
  selection, and multi-patch writes retain successful-write counts and per-item
  errors after a later address fails to resolve.
- **IPC timeouts and late replies.** Canceled asynchronous I/O completes before its
  buffers are released. Ambiguous write/response failures invalidate ordinary
  requests so a late reply cannot answer a subsequent request. Address-space
  resolution waits cover the backend scan and application stages.
- **Clearer operation failures.** Shellcode requests report backend/transport errors
  and explicit invalid-target-state refusals instead of guessing allocation or
  thread-creation failures. Breakpoint types come from registered kinds rather
  than numeric ID ranges, and failed protection restoration/cache flushing is
  reported as a memory-write failure.
- **Kernel-stub compatibility and shutdown.** The GDB RSP client handles delayed or
  unsolicited stops, console output and shorter register packets. Detach removes
  owned breakpoints and retains the session if cleanup fails. DAP shutdown wakes
  and joins its reader without polling or missed wakeups.
