# VEH Debugger v1.2.4

This release adds selected-CPU kernel tracing and hardware instruction events
through supporting backends. Process traces now save full results to files by
default, with compact receipts and offline readers for longer captures.

## Upgrade notes

- Process `veh_trace_basic_blocks` now defaults to `output_mode="file"`. Read the
  returned `output_file.path` for the full JSON, or explicitly choose
  `output_mode="inline"` to retain the previous response style. JSONL and
  caller-selected new paths are also supported; callers own file retention.
- Kernel and CR/MSR/I/O collection use supporting external backends, which are
  not included in these packages. Availability follows advertised capabilities.
  The built-in VEH DLL retains its process debugging features.
- Hardware collection is opt-in through `collect_hardware_events=true`.
  Existing process and KD captures keep their wire contracts when it is off.
  Process hardware capture uses its own IPC capability; KD hardware capture
  independently negotiates TraceHW v1.
- KD capture requires an explicit connection and a halted machine. It observes
  the selected CPU across user/kernel transitions, rather than following a
  migrating OS thread. Whole-machine execution remains a direct-call operation.
- Saved files can be complete even when the capture stopped at a step or file
  limit. Check `storage_complete` separately from `capture_complete`; unknown
  values and uncertain execution counts remain explicit.

## Added

- **Selected-CPU kernel traces.** Use `execution_context="kd"` with the existing
  basic-block tool for observed blocks, edges, instruction bytes and optional
  register snapshots. TraceBB v1 retains its 4,096-step limit; streaming v2
  supports up to 5,000,000 steps with bounded replies and portable raw files.
- **Hardware instruction events.** Select `control_register`, `msr` and
  `io_port` with `hardware_kinds` to record MOV CR, RDMSR/WRMSR and scalar
  IN/OUT observations. Events preserve actual transferred values, unknown
  before/after state, exact 64-bit data and scope-exit reasons.
- **Independent KD hardware transport.** Instructions and hardware events use
  separate paginated streams. Both are saved before continuation is
  acknowledged, and terminal buffers are released after artifacts are ready.
  Compact records can omit register snapshots.
- **Offline trace inspection.** Read saved hardware events with `read_events`,
  summarize them with `analyze_events`, and page saved KD instructions with
  `read_capture`. Immutable reads support direct calls, batches and breakpoint
  actions, including after the original KD connection closes.
- **Optional peer CPU execution.** `run_peer_cpus=true` uses the relevant
  protocol's independently advertised policy. Capture stays on the selected CPU;
  uncertain code or instruction completion stops with the verified prefix.
- **Analysis and VM guest profiles.** `--profile=analysis` exposes 41 common
  analysis tools. `--profile=vmguest` adds process discovery and whole-machine
  control for 43 tools. Existing profiles and lazy tool discovery remain available.

## Changed

- Basic-block result files return paths, sizes, SHA-256 hashes, counts and
  explicit loss/truncation metadata. Separate `events_output="file"` remains
  the ordered-event streaming option on supported local backends.
- Hardware capability negotiation also works for ordinary host/process
  hypervisor connections; guest target scope is not mandatory.
- README examples, extension description, CLI help and MCP descriptions explain
  process versus KD capture, hardware selection and offline artifact inspection.

## Fixed

- Explicit peer-CPU debug stops prevent automatic KD continuation, preserving
  the validated prefix.
- Cancelled event drains no longer appear as confirmed EOF or complete files.
- Event receiving enforces negotiated per-instruction limits, and offline
  readers reject malformed basic-event payloads.
- Ordinary guest file event captures retain requested timeouts up to 30 minutes
  without enabling hardware collection or silently shortening the request.
