# VEH Debugger v1.2.0

This release adds a set of memory, symbol, thread, and assembly tools that close
the gaps against a traditional debugger, plus lossless file-backed trace event
streaming. It also fixes a trace defect that mis-recorded control flow.

## Upgrade notes

- No breaking changes. Existing tools, arguments, and the default `lite` profile
  are unchanged. The new tools are reached through the `full` profile or the
  `veh_toolbox` gateway, like the other specialized tools.
- `veh_trace_basic_blocks` behaves exactly as before unless you pass the new
  `events_output=file`; only then are ordered events streamed to a file.

## Added

- **`veh_search_memory`** searches target memory for an AOB pattern (`??` byte and
  `4?` nibble wildcards), a string (ascii/utf8/utf16), or a numeric value
  (i8-u64, f32/f64, ptr), with address-range/module, writable, executable, region
  type, and alignment filters. Breakpoint bytes compare as the original code, the
  search's own pattern is never reported, and `next_start` resumes a capped result.
- **`veh_memory_map`** lists virtual memory regions with state, protection, type,
  and owning module, scoped to a range or module and paged through `next_start`.
- **`veh_value_scan`** is a Cheat Engine style value scan session
  (`first`/`next`/`results`/`reset`): exact/range/unknown first scans and
  change-aware next scans, with the candidate set kept inside the target.
- **`veh_symbolize`** resolves up to 256 addresses to `module!function+offset`
  (PDB symbol, else nearest export, else `module+RVA`) with source file and line,
  using the same resolution as stack frames. Works while the target runs.
- **`veh_display_type`** shows a PDB struct/class/union layout like WinDbg `dt`:
  member offsets, types, sizes, bitfields, base classes, and nested members up to
  a depth, and with an address it reads scalar/pointer/enum/bitfield values.
- **`veh_freeze_thread`** freezes or thaws one thread; a frozen thread stays
  suspended across `veh_continue` until thawed, and detach thaws all.
- **`veh_assemble`** assembles Intel-syntax x86/x64 text (AsmJit + AsmTK) at an
  address, computing relative `jmp`/`call`/`jcc` and rip-relative operands, and
  can patch the target with `write=true`. Verified by reassembling thousands of
  disassembled instructions on both architectures.
- **`veh_protect_memory`** changes page protection through `VirtualProtect`,
  `NtProtectVirtualMemory`, or a direct syscall (to bypass user-mode ntdll hooks),
  reporting the previous protection and the method actually applied.
- **File-backed ordered trace event streams**: `veh_trace_basic_blocks` can write
  interleaved block/edge, memory, and register events to a versioned `.vte`
  artifact instead of the inline per-kind caps and the 16 MiB control-pipe limit.
  Preallocated target buffers apply lossless backpressure (the traced thread waits
  rather than dropping events), the file limit defaults to and caps at 4 GiB and
  truncates only between complete records, and `tools/read_trace_event_stream.py`
  converts the format to JSON Lines.

## Changed

- Disassembly always prints memory operand sizes (`dword ptr`, `qword ptr`).
  Zydis omitted them for forms like `dec [rax+0x30]` that are ambiguous to read
  and impossible to reassemble; `veh_disassemble`, trace listings, and the DAP
  disassembly view now show them on every memory operand.
- New memory, symbol, and thread operations that depend on target state run as
  in-target IPC commands, so a future backend can implement the same commands.

## Fixed

- Traces recorded unexecuted instructions after an indirect jump or return. When
  a `jmp reg`/`ret` landed inside a linearly decoded block, the edge target and
  entered block were recorded as that block's start instead of the executed
  address, so tools replaying the trace treated the skipped instructions as
  executed and their register models drifted. Edge targets and blocks now use the
  executed address; the step after an edge lands on the edge target.
- A single IPC command that ran longer than the DLL's idle heartbeat window (for
  example a large memory search) could trigger an emergency cleanup; the idle
  timer now restarts when the command finishes.
