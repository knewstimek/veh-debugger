# VEH Debugger v1.1.18

## Upgrade notes

- `veh_batch` steps, targeted-capture setup steps, and breakpoint actions now run the same implementations as direct MCP calls. Scripts that relied on the old batch-only behavior may need updates: thread-scoped tools require `threadId`, size/range validation and error messages match direct calls, and `veh_enum_locals` returns `variables` with typed values instead of `locals` with raw hex.
- Session lifecycle tools (`veh_attach`, `veh_launch`, `veh_detach`, `veh_terminate`) and the orchestrators `veh_batch`, `veh_targeted_capture`, and `veh_toolbox` are rejected inside nested steps.

## Changed

- Batch steps and breakpoint actions can now call `veh_exception_info`, `veh_read_pointer_chain`, `veh_resolve_imports`, and `veh_trace_calls`; `veh_step_*` results include `instructionPointer`.
- The default `lite` MCP profile also exposes `veh_attach` and `veh_registers`, so attach-first sessions and register inspection need no `veh_toolbox` round-trip.
- `veh_registers` accepts `fields` in direct calls, and `veh_stack_trace` adds `count`.
- MCP tool failures are flagged `isError: true`, including failures returned through `veh_toolbox`.

## Fixed

- Step over (F10) could terminate the debuggee with `STATUS_BREAKPOINT` because IPC requests carried uninitialized bytes; observed on x86 and timing-dependent.
- DAP `continue` resumed only the selected thread since v1.1.15; it again resumes all threads unless `singleThread` is requested.
- Step over no longer stops twice on a function's last line when the following source line has no code.
- 32-bit targets: pointer evaluation (`[addr]`, `*addr`, `0x...`, `fs:[off]`) in MCP and in VS Code watch/hover reads 4 bytes instead of merging the next dword.
- Basic-block traces of overlapping or obfuscated code (e.g. VMProtect handlers) keep hit counts, code bytes, and memory events for instructions executed off the linear decode, so code capture is complete.
- Traces record CALL return-address writes at the decremented stack pointer instead of one slot higher.
- Batch steps wait for step completion, and batch address arguments use the current address parser (literal arithmetic, overflow rejection).
